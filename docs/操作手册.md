## 零、前置条件速查

| 项 | 值 | 说明 |
|---|---|---|
| Node.js | ≥ 18（本机实测 24.16.0） | `node -v` |
| MySQL | 8.4.9 免安装版，位于 `D:\APP\MySQL` | 见下方启停脚本 |
| 数据库 | `127.0.0.1:3306` / 用户 `root` / 库 `book_db` | 密码以 `BookBackendManage/.env` 为准 |
| 服务端口 | `3000` | 访问地址 <http://localhost:3000> |
| 浏览器 | Chrome（仅端到端脚本需要，手工验收用任意浏览器） | 脚本会自动探测 Chrome 路径 |

> 家里/机房若装了完整版 MySQL 并以 Windows 服务方式常驻，也可直接用，只要
> `127.0.0.1:3306` 可连、账号密码与 `.env` 一致即可，不必使用 `D:\APP\MySQL`。

### MySQL 启停脚本（免安装版自带）

```bat
D:\APP\MySQL\start-mysql.bat   :: 启动，弹出最小化的 mysqld 控制台窗口
D:\APP\MySQL\stop-mysql.bat    :: 停止（内部走 mysqladmin shutdown）
```

> **注意**：`start-mysql.bat` 是以 `--console` 前台方式拉起 `mysqld` 的，
> 那个最小化的「MySQL 8.4.9」窗口就是数据库进程本身，**关掉窗口等于杀掉数据库**。
> 正常停止请用 `stop-mysql.bat`。

## 一、启动系统

### 第 1 步：启动 MySQL

双击 `D:\APP\MySQL\start-mysql.bat`，或在任意终端执行：

```bat
D:\APP\MySQL\start-mysql.bat
```

脚本会自己等待端口就绪，看到下面这行即为成功：

```
[成功] MySQL 已启动并监听 127.0.0.1:3306
```

**手工确认端口**（可选）：

```bash
netstat -ano | findstr ":3306"
# 期望能看到  TCP  127.0.0.1:3306  ...  LISTENING   <PID>
```

### 第 2 步：配置数据库连接（仅首次）

复制示例文件、按本机实际情况填写密码：

```bash
cp BookBackendManage/.env.example BookBackendManage/.env
```

`BookBackendManage/.env` 内容：

```ini
PORT=3000
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=root123456
DB_NAME=book_db
DB_CONNECTION_LIMIT=10
```

> `.env` 含数据库密码，已在 `.gitignore` 中排除，**不会**进入版本库。
> 本机已存在该文件，验收时通常无需重复创建。

### 第 3 步：安装依赖 + 初始化数据库（仅首次）

```bash
npm install       # npm workspaces，会在根目录装齐后端依赖
npm run db:init   # 依次执行 sql/01_schema.sql 与 sql/02_seed.sql
```

`db:init` 成功时输出建库、建表与灌数过程，结束后：

- `book_type` 8 条、`book_info` 12 条（试卷要求每表 ≥ 5 条）

> `01_schema.sql` 自身带 `CREATE DATABASE`，可重复执行；
> 它会先 `DROP TABLE IF EXISTS` 再重建，因此 **`db:init` 会清空并重置 `book_db`**。

### 第 4 步：启动 Express 服务

```bash
npm run dev     # 开发模式：改动源码自动重启
# 或
npm start       # 普通模式
```

看到以下输出即为启动成功：

```
图书借阅系统-后台管理
  服务地址：http://localhost:3000
  数据库：127.0.0.1:3306/book_db
```

### 第 5 步：打开系统

浏览器访问 <http://localhost:3000>，进入「图书借阅系统-后台管理」首页（列表页）。

**这个终端窗口要一直开着**——它就是服务进程。验收结束后按 `Ctrl+C` 关闭（见第四节）。

### 4. 新增图书（图-4 / 图-5）

**操作**：列表页点「新增」。

**预期（图-4，打开即可见）**：

- 标题「新增图书信息」，表单两列布局
- 8 个字段：图书编号 / 图书名称 / 图书类型 / 作者 / 出版社 / 是否借阅 / 入库人 / 入库时间
- **星号 `*` 只出现在 6 个必填项后面**：图书编号、图书名称、图书类型、是否借阅、入库人、入库时间
  （作者、出版社没有星号）
- 入库人默认填入「系统管理员」
- 是否借阅默认选中「未借阅」
- 入库时间默认当天日期
- 图书类型下拉首项是占位项「——请选择——」，其余选项来自 `book_type` 表

**验证必填校验**：

1. 什么都不填，直接点「保存」
   → 弹窗「图书编号不能为空」，**停留在本页**，不跳转
2. 只填图书编号等部分字段
   → 依次提示缺失的必填项

**验证新增成功（图-5）**：

1. 填一组**没被占用**的编号（如 `BK900001`）+ 图书名称 + 选类型，其余可留空
2. 点「保存」
   → 弹窗「新增成功！」
   → 自动跳回列表页
   → 列表总记录数变为 **13 条**，新书因入库时间最新而**排在首位**
3. 验收完请把这条测试数据删掉（列表里点「删除」），恢复 12 条

**验证编号重复（图-5 失败分支）**：

1. 再点「新增」，图书编号填一个**已存在**的（如 `BK000001`）
2. 点「保存」
   → 弹窗「新增失败！ / 图书编号「BK000001」已存在，请更换」
   → 停留在新增页

### 7. 命令行自检（可选）

不想开浏览器时，可用 curl 直接确认接口通不通：

```bash
curl -s "http://localhost:3000/api/books?page=1&pageSize=5"
curl -s "http://localhost:3000/api/book-types"
```

## 三、自动化验收（三条命令）

三条命令从三个角度复核系统，都**不依赖人工点击**：

```bash
npm test           # ① 接口回归测试（Vitest + Supertest）  113 条
npm run test:web   # ② 前端静态资源检查                    33 项
npm run test:e2e   # ③ 页面端到端验收（真实 Chrome）       58 条
```

| 命令 | 需要 MySQL | 需要服务已启动 | 需要 Chrome |
|---|---|---|---|
| `npm test` | ✅ | ❌（脚本自建进程） | ❌ |
| `npm run test:web` | ❌ | ❌ | ❌ |
| `npm run test:e2e` | ✅ | ✅ 需先 `npm start` | ✅ |

### ① `npm test`

在**独立库 `book_db_test`** 上运行，每次由 `globalSetup` 直接执行交付的
`sql/01_schema.sql` + `sql/02_seed.sql` 重建，因此结果可重复，且**不污染开发库 `book_db`**。

期望输出结尾：

```
 Test Files  8 passed (8)
      Tests  113 passed (113)
```

### ② `npm run test:web`

校验四个页面齐全、页面引用的本地资源都存在、**不引用任何外部地址**（断网也能打开）、
jQuery 确为试卷规定的 1.8.3。

期望输出结尾：

```
前端静态资源检查：通过 33 项
全部通过
```

### ③ `npm run test:e2e`

用 Puppeteer 驱动**本机真实 Chrome**，把试卷图-1 ~ 图-9 的交互链路全部走一遍，
包括弹窗文案、只读字段防篡改、删除取消不生效、返回后条件保留等。
运行前**必须先启动服务**（第 4 步）。

```bash
npm start          # 终端 A：启动服务
npm run test:e2e   # 终端 B：跑端到端验收
```

脚本会自动探测 Chrome 路径；若探测不到，可显式指定：

```bash
node BookBackendManage/scripts/e2e-pages.js --chrome="C:/Program Files/Google/Chrome/Application/chrome.exe"
```

期望输出结尾：

```
断言：58/58 通过
全部通过
```

截图默认写到系统临时目录（**不污染仓库**），路径会在输出末尾打印。
仓库内已归档一份到 [`docs/screenshots/`](./screenshots/)。

## 四、关闭系统

关闭顺序：**先停 Express，再停 MySQL**（反过来会让服务端连接池报错，虽不影响数据但日志难看）。

### 1. 停止 Express 服务

回到第 4 步启动服务的那个终端窗口，按：

```
Ctrl + C
```

服务会优雅退出，输出：

```
^C
收到 SIGINT，正在关闭服务 ...
服务已关闭
```

> `server.js` 里注册了 `SIGINT` / `SIGTERM`：先停收新请求、再释放数据库连接池，不会留下悬空连接。

**如果终端窗口被直接关掉了**（没走 Ctrl+C），进程可能变成孤儿进程继续占着 3000 端口，
下次启动会报 `EADDRINUSE`。处理方法：

```bash
netstat -ano | findstr ":3000"          # 找到 PID
taskkill /PID <上面查到的PID> /F         # 结束它
```

### 2. 停止 MySQL

```bat
D:\APP\MySQL\stop-mysql.bat
```

成功输出：

```
[成功] MySQL 已停止
```

**替代方式**（任意终端）：

```bash
"D:/APP/MySQL/bin/mysqladmin.exe" -u root -proot123456 --host=127.0.0.1 --port=3306 shutdown
```

> 也可以在「MySQL 8.4.9」那个最小化窗口里直接 `Ctrl+C` 或关闭窗口，
> 但那是**强杀**，正常验收请优先用 `stop-mysql.bat`。

### 3. 确认已全部关闭

```bash
netstat -ano | findstr ":3306"   # 无输出 = MySQL 已停
netstat -ano | findstr ":3000"   # 无输出 = Express 已停
```

两条都无输出，即系统已完全关闭。数据库文件保存在 `D:\APP\MySQL\data`，
下次按第 1 步重新启动即可，**数据不会丢**。

### 4.（可选）恢复出厂数据

验收过程中若增删改过数据，想让 `book_db` 回到试卷示例的 12 条：

```bash
# 先启动 MySQL，然后
npm run db:init
```

## 五、常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动服务报 `EADDRINUSE :::3000` | 3000 端口被占（多为上次没关干净的孤儿 node 进程） | `netstat -ano \| findstr ":3000"` 找到 PID → `taskkill /PID <PID> /F` |
| 启动服务报 `缺少必填环境变量 DB_USER，请检查 BookBackendManage/.env` | `.env` 不存在或没填 | 复制 `.env.example` 为 `.env` 并填写 |
| 接口报数据库连接失败 / `ECONNREFUSED 127.0.0.1:3306` | MySQL 没启动 | 执行 `D:\APP\MySQL\start-mysql.bat` |
| 报 `ER_ACCESS_DENIED_ERROR` | `.env` 里密码与 MySQL 实际密码不符 | 核对 `DB_PASSWORD` |
| 报 `Unknown database 'book_db'` | 没初始化数据库 | `npm run db:init` |
| 页面打开是空表 / 显示「加载失败」 | 服务没起来或数据库断了 | 看启动服务的终端有没有报错 |
| 页面样式全丢、像纯文本 | 静态资源 404 | 在根目录执行 `npm run test:web` 定位缺哪个文件 |
| `npm test` 报连不上 `book_db_test` | MySQL 没启动 | 启动 MySQL 后重跑；测试库由脚本自动重建，无需手工建 |
| `npm run test:e2e` 报找不到 Chrome | 未装 Chrome 或装在非常规路径 | 用 `--chrome="完整路径"` 显式指定 |
| `npm run test:e2e` 报页面打不开 | 忘了先启动服务 | 另开终端 `npm start` 后再跑 |
| 浏览器打开首页没有任何数据、也看不到报错 | 查询条件残留在地址栏 | 直接访问不带参数的 <http://localhost:3000/> 即为「显示全部图书」 |

## 六、一页速查表

```bash
# ---------- 启动 ----------
D:\APP\MySQL\start-mysql.bat        # 1. 启动数据库
npm run db:init                     # 2. 初始化（仅首次）
npm run dev                         # 3. 启动服务
# 4. 浏览器打开 http://localhost:3000

# ---------- 验收 ----------
npm test                            # 接口回归 113 条（自建测试库）
npm run test:web                    # 前端静态检查 33 项
npm run test:e2e                    # 页面端到端 58 条（需服务已启动 + Chrome）

# ---------- 关闭 ----------
Ctrl+C                              # 1. 在服务终端停 Express
D:\APP\MySQL\stop-mysql.bat         # 2. 停数据库
netstat -ano | findstr ":3000 :3306"  # 3. 确认端口已释放（无输出 = 已关干净）

# ---------- 救急 ----------
netstat -ano | findstr ":3000"      # 查占用 3000 的进程
taskkill /PID <PID> /F              # 强杀孤儿进程
```
