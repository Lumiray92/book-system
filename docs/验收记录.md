## 三、浏览器端到端验收（真实 Chrome）

脚本 [`server/scripts/e2e-pages.js`](../server/scripts/e2e-pages.js) 用 Puppeteer 驱动真实 Chrome
走完试卷图-1 ~ 图-9 的全部交互链路，共 **58 条断言，58 条通过**。

```bash
npm start           # 另开一个终端启动服务
npm run test:e2e    # 需本机已安装 Chrome
```

> 该脚本需要真实浏览器，因此不进 CI；CI 只跑接口回归测试与静态资源检查。

### 覆盖的关键链路

| 场景 | 断言要点 |
|---|---|
| 图-1 默认列表 | 每页 5 条、共 12 条 3 页、表头 8 列、入库时间为「年-月-日」、隔行变色生效、分页条含「共3页」「到第 页 确定」、操作列为「查看/修改/删除」 |
| 图-2 查询 | 结果为 1 条且编号正确、输入框保留条件、条件写入地址栏、无结果时提示「未查询到」 |
| 图-3 查看 | 标题正确、**8 个字段全部只读**、各字段值与库中一致、类型显示名称而非 id、返回后查询条件与结果均保留 |
| 图-4 新增 | 入库人默认「系统管理员」、是否借阅默认「未借阅」、入库时间默认当天、类型下拉来自 `book_type` 表且首项为占位、**星号只标在 6 个必填项上** |
| 图-4 校验 | 编号留空被拦下且停留在本页 |
| 图-5 提示 | 编号重复提示「图书编号「BK000023」已存在，请更换」；成功后提示「新增成功！」并跳回列表；总数变为 13 条、新书排在首位 |
| 图-6 修改 | 回填正确、**入库人只读、入库时间只读**；强制解除只读并篡改后提交，库中仍是原值 |
| 图-7 提示 | 提示「修改成功！」并跳回列表；可编辑字段已更新 |
| 图-8 删除确认 | 弹出 `confirm('确定删除该图书信息？')`；**取消则记录仍在** |
| 图-9 删除提示 | 提示「删除成功！」并跳回列表；无结果时提示「未查询到」且分页条隐藏；回到首页总数复原为 12 条 |

### 实际捕获的弹窗文本

原生 `alert` / `confirm` 由浏览器绘制，不在页面截图范围内，
因此用 Puppeteer 的 `dialog` 事件记录实际文本，作为图-5 / 图-7 / 图-8 / 图-9 的凭据：

```
[alert]   图书编号不能为空
[alert]   新增失败！
          图书编号「BK000023」已存在，请更换
[alert]   新增成功！
[alert]   修改成功！
[confirm] 确定删除该图书信息？     ← 取消这次
[confirm] 确定删除该图书信息？     ← 确认这次
[alert]   删除成功！
```

提示语与试卷图-5、图-7、图-8、图-9 的文字一致。
