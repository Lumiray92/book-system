## 一、统一视觉规范

| 项 | 取值 | 说明 |
|---|---|---|
| 字体 | `Microsoft YaHei, 微软雅黑, Arial, sans-serif` | 中文界面常规选择 |
| 页面背景 | `#f0f2f5` | 浅灰，衬托白色内容区 |
| 内容区 | 白色卡片，`border-radius` + 轻投影 | 列表页较宽，表单页收窄 |
| 主色 | 蓝色 `#2b7de9` | 链接与按钮悬停态 |
| 表头 | 深灰 `#6d6d6d` 底 + 白色文字 | 对齐图-1 |
| 隔行变色 | 偶数行 `#f2f2f2` | 试卷明确要求 |
| 必填标记 | 红色 `*`，位于**输入框之后** | 对齐图-4 的样式 |
| 按钮 | 灰底描边，悬停转蓝 | 新增/查询/保存/修改/返回/确定 统一 |

页面宽度：

- 列表页 `.container` —— 承载 8 列表格
- 查看/新增/修改页 `.container-narrow` —— 表单两列布局，避免输入框过宽

## 二、列表页 `web/index.html`（图-1 / 图-2）

```
┌──────────────────────────────────────────────────────────────┐
│                     图书借阅系统-后台管理                      │
│                                                              │
│              图书名称: [__________]  [查询]                    │
│                                                              │
│  [新增]                                                       │
│  ┌────────┬────────┬──────────┬────────┬────────┬─────┬────┐ │
│  │图书编号│图书分类│ 图书名称 │  作者  │ 出版社 │入库…│操作│ │
│  ├────────┼────────┼──────────┼────────┼────────┼─────┼────┤ │
│  │BK000023│  科技  │企业应用… │(英) …  │机械工业│2014…│查看│ │
│  │BK000024│  科技  │精通Hib…  │  刘洋  │电子工业│2014…│修改│ │
│  └────────┴────────┴──────────┴────────┴────────┴─────┴────┘ │
│                                                              │
│   上一页 ◀  1  2  3  ▶ 下一页  共3页  到第[  ]页 [确定]       │
└──────────────────────────────────────────────────────────────┘
```

**列宽比例**：图书编号 11% / 图书分类 9% / 图书名称 18% / 作者 13% /
出版社 17% / 入库时间 11% / 是否借阅 8% / 操作 13%。

**交互**

| 元素 | 行为 |
|---|---|
| 打开首页（无参数） | 显示全部入库图书，按入库时间降序（试卷第 1 条） |
| 查询 | 按图书名称模糊匹配，条件写入地址栏 |
| 页码 / 上一页 / 下一页 / 到第 N 页 | 翻页，条件一并保留 |
| 查看 / 修改 | 携带 `id`、`bookName`、`page` 跳转，返回时可还原 |
| 删除 | 先 `confirm` 确认，成功后回到列表并提示 |

**为什么查询条件放在地址栏而不是 localStorage**

试卷要求「点击返回按钮时……列表页需保留查询条件和查询结果」，
同时第 1 条又要求「默认显示全部的入库图书信息」。
把条件放进 URL 可以同时满足两者：

- 带参数进入 → 还原条件与结果（满足「保留」）
- 不带参数打开首页 → 一定是全部图书（满足「默认」）

用 localStorage 记忆条件会让「直接打开首页」也被上一次的查询条件污染，
违反第 1 条。刷新页面时地址栏同样有效，因此不损失任何便利。

## 三、查看页 `web/detail.html`（图-3）

两列表单，**所有字段只读**：文本输入框 `readonly`，下拉框与日期框 `disabled`。

| 左列 | 右列 |
|---|---|
| 图书编号 | 图书名称 |
| 图书类型（显示**类型名称**，非 id） | 作者 |
| 出版社 | 是否借阅 |
| 入库人 | 入库时间 |

底部单按钮「返回」，回到列表页并保留查询条件与页码。

## 四、新增页 `web/add.html`（图-4 / 图-5）

| 左列 | 右列 | 默认值 |
|---|---|---|
| 图书编号 `*` | 图书名称 `*` | — |
| 图书类型 `*` | 作者 | 类型下拉首项「——请选择——」 |
| 出版社 | 是否借阅 `*` | 未借阅 |
| 入库人 `*` | 入库时间 `*` | 系统管理员 / 当天 |

- 星号仅标在试卷正文与图-4 明确的 6 个必填项上；**作者、出版社不标**。
- 图书类型下拉的选项由 `GET /api/book-types` 从 `book_type` 表动态填充，
  页面不写死（试卷明确要求）。
- 底部「保存」「返回」两个按钮（图-4）。

**提示语**：校验失败 → 停在当前页并弹出具体原因；保存成功 → 弹出「新增成功！」后跳回列表；
服务端拒绝 → 弹出「新增失败！」并附具体原因（图-5）。

## 五、修改页 `web/edit.html`（图-6 / 图-7）

与新增页同一套字段与校验，差异在于：

- 进入页面先按 `id` 取回原数据回填
- **入库人 `readonly`、入库时间 `disabled`**（试卷要求不可修改）
- 底部按钮为「修改」「返回」

只读仅是前端表现，服务端在 `updateBook` 中同样强制沿用库中原值，
绕过页面直接提交也改不动（回归测试 `books.update.test.js` 有专门用例覆盖）。

**提示语**：成功 → 「修改成功！」后跳回列表；失败 → 「修改失败！」+ 原因（图-7）。

## 六、删除交互（图-8 / 图-9）

```
[删除] → confirm('确定删除该图书信息？')
           ├─ 取消 → 停在列表，不做任何改动
           └─ 确定 → DELETE /api/books/:id
                       ├─ 成功 → 回列表 + 「删除成功！」
                       └─ 失败 → 回列表 + 「删除失败！」+ 原因
```

无结果时列表区显示「未查询到符合条件的图书信息」，分页条隐藏。

页面为纯静态 HTML + CSS + jQuery 1.8.3（试卷规定版本），
