## 与试卷的偏差说明

以下为**有意偏离**，均已在代码注释中标注原因：

### 1. 工程命名（第 2 条）

试卷要求 Web 工程命名为 `BookBackendManage`。
本项目按 `quiz07.md` 的「前后端」结构组织为单仓库：

- 仓库：`book-system`
- 服务端（对应原卷的 Web 工程）：`server/`
- 前端页面：`web/`

如需严格对齐，可把 `server/` 重命名为 `BookBackendManage/`。

### 2. 声明式事务（第 9 条）

「声明式事务」源自 Spring 的 `@Transactional`，依赖 AOP 容器，Express 无对应机制。
本项目以 `withTransaction(fn)` 提供等价能力：

- 事务边界由该包装器统一接管，业务代码**不出现** `begin` / `commit` / `rollback`
- 符合试卷「以代码方式实现事务不得分」的原始意图（即事务不应散落在业务逻辑里）

### 3. 两处字段与页面的出入

| 项 | 试卷原文 | 处理方式 |
|---|---|---|
| 必填项范围 | 正文列 6 项必填，但表结构中 `bookAuthor` / `publishPress` / `publishDate` 标注「非空」 | 表单按正文与图-4 星号只校验 6 项；作者、出版社未填时以空串入库，兼顾非空约束 |
| 出版日期 | 表结构中「非空」，但图-1 ~ 图-9 均未出现该字段 | 不在页面暴露，新增时由服务端默认取入库时间当天 |

### 4. 图书作者字段类型

试卷表结构将 `bookAuthor` 标注为「整数」，但示例数据为「金庸」「Martin Fowler」等姓名。
按实际语义采用 `VARCHAR(50)`。
